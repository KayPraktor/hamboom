# `@hamboom/realtime`

سرورِ WebSocketِ همگام‌سازیِ بلادرنگ — اتاق، پایداری، حضور، خوشه.
**بخشِ سرورِ ماژول M2.**

> برای کار کردن **روی** این سرور، [`CLAUDE.md`](CLAUDE.md) را بخوان (خط قرمزها و
> شرحِ کاملِ آنچه هر گام قفل کرده). این فایل برای کسی است که می‌خواهد اجرایش کند
> یا در M3 به آن وصل شود.

## اجرا

```bash
pnpm db:up && pnpm db:migrate          # postgres + redis
node --env-file-if-exists=.env apps/realtime/src/main.ts
```

یا برای دمو و E2E، همان نود با سیم‌کشیِ سبک‌تر:

```bash
pnpm rt:dev                             # حافظه‌ای — بدونِ داکر
node scripts/rt-dev-server.ts <port> --pg   # همان نود با Postgres + Redisِ واقعی
```

**متغیرهای محیطی** در [`.env.example`](../../.env.example) اند. پنج‌تای مهم:

| متغیر | پیش‌فرض | چیست |
|---|---|---|
| `RT_PORT` | ۳۰۰۱ | — |
| `RT_MAX_DOC_BYTES` | ۵۰MB | سقفِ سختِ هر بورد → `DOC_TOO_LARGE`. ⚠️ **گیتِ موثر نیست** — پایین |
| `RT_MAX_ROOMS_PER_NODE` | ۵۰۰ | ⚠️ **برای بوردهای بزرگ گیت نیست** — پایین |
| `RT_SNAPSHOT_EVERY_UPDATES` | ۵۰۰ | آستانه‌ی فشرده‌سازی |
| `RT_DEV_JWT_SECRET` | — | ★ فقط تا M3؛ سرور با `APP_ENV=production` **بالا نمی‌آید** |

## مسیرها

| مسیر | چیست |
|---|---|
| `GET /rt?board=<uuid>&token=<jwt>` | upgradeِ WebSocket |
| `GET /healthz` | زنده است؟ در خاموشی هم **سبز می‌مانَد** |
| `GET /readyz` | ترافیک بگیرم؟ در خاموشی **قرمز** می‌شود (خروج از لودبالانسر) |

⚠️ `board` باید **UUIDِ خام** باشد. `brd-<uuid>` در `onJoin` می‌ترکد و کلاینت یک
`FORBIDDEN`ِ عمومی می‌بیند — fail-closed درست کار می‌کند ولی گیج‌کننده است
(یادداشتِ M3: خطای **شکل** بهتر است کدِ خودش را داشته باشد).

## ★ آنچه تضمین می‌کند

- **کار از دست نمی‌رود** — update **قبل از** ackِ کلاینت در Postgres می‌نشیند
  ([ADR-009](../../ARCHITECTURE_DECISIONS.md#adr-009)). آزموده با `SIGKILL` و
  دیتابیسِ واقعی: `pnpm rt:durability`.
- **لاگ بی‌کران رشد نمی‌کند** — هر ۵۰۰ update فشرده و قدیمی‌ها حذف می‌شوند.
  ترتیبِ حذف **امن** است: بازسازی → ردِ شکافِ علّی → نوشتن → **بازخوانی از انبار**
  → ثبتِ رکورد → و تازه بعدش `prune`.
- **نقش روی هر update سنجیده می‌شود**
  ([ADR-012](../../ARCHITECTURE_DECISIONS.md#adr-012))، نه فقط هنگام اتصال. تصمیمش
  **فقط** در [`src/permission.ts`](src/permission.ts) است.
- **چندنودی است** ([ADR-006](../../ARCHITECTURE_DECISIONS.md#adr-006) فاز ۲) — قفلِ
  صاحب با اسکریپتِ Lua، و **فقط صاحب می‌نویسد**.
- **مودبانه می‌رود** — بدرقه با کدِ **۱۰۰۱** → تخلیه → snapshot → پس دادنِ قفل.
- **مرزِ اعتماد اینجاست** — عنصرِ نامعتبر **قرنطینه** می‌شود (شمرده و لاگ، نه
  بی‌صدا) و یک عنصرِ خراب کلِ بورد را خالی نمی‌کند.

## ★★ سقف‌های واقعی — اندازه‌گیری‌شده، نه فرض

جزئیات و روش در [`docs/realtime-baseline.md`](../../docs/realtime-baseline.md).

| سنجه | عدد |
|---|---|
| بوردِ ۵۰۰۰ عنصری — حجمِ سند | **۳٫۶۶MB** (۷٫۳٪ از `RT_MAX_DOC_BYTES`) |
| بوردِ ۵۰۰۰ عنصری — **حافظه‌ی هر اتاق** | **۷۶MB** (~۱۵KB به‌ازای هر عنصر) |
| بارگذاریِ سرد / گرم | ۵۲۷–۹۲۱ms / ۱۶۰–۴۲۱ms |
| تاخیر — آرام (۵۰ کلاینت، یک نویسنده) | p50 **۵ms** · p95 **۸–۱۰ms** |
| تاخیر — رگبار (۵۰ نویسنده‌ی هم‌زمان) | p50 **۸۷–۱۰۳ms** · p95 **۱۴۹–۱۷۶ms** |

⚠️ **`RT_MAX_DOC_BYTES` گیتِ موثر نیست، حافظه است.** ۵۰MB معادلِ ~۶۵٬۰۰۰ عنصر
است ولی چنان بوردی ~**۱GB** حافظه‌ی نود را می‌گیرد. و
**`RT_MAX_ROOMS_PER_NODE=۵۰۰` برای بوردهای بزرگ گیت نیست**: ۵۰۰ اتاقِ ۵۰۰۰عنصری
یعنی ~**۳۸GB**؛ روی نودِ ۴گیگی حدودِ **۵۰** اتاق جا می‌شود.

★ **و تاخیرِ رگبار باگ نیست، معامله است:** ۱۰/۲۵/۵۰ نویسنده → ۱۹/۴۳/۸۴ms، خطی،
~۱٫۷ms به‌ازای هر نویسنده. این صفِ سریالیِ `seq`
([ADR-037](../../ARCHITECTURE_DECISIONS.md#adr-037)) پشتِ «پخش بعد از append» است
(ADR-009) — بهایی که پرداختیم تا هیچ همتایی چیزی نبیند که ممکن است پایدار نشده باشد.

## ★ سنجه‌های زنده — هر هفت باگی گرفتند که تست‌های واحد از رویش رد شده بودند

```bash
pnpm rt:durability   pnpm rt:compaction   pnpm rt:permission   pnpm rt:presence
pnpm rt:cluster      pnpm rt:shutdown     pnpm rt:reconnect    pnpm rt:bench
```

⚠️ **این‌ها `skip` نمی‌شوند و نباید بشوند.** اگر پایداری، مجوز، حضور، خوشه،
خاموشی یا اتصالِ مجدد را دست زدی، **هر هفت** را بزن — باگِ گام ۴٫۶ را سنجه‌ی گام
۴٫۴ گرفت، نه سنجه‌ی خودش.

★ **و خودِ سنجه هم باید خودآزمون باشد.** هر کدام با شکستنِ عمدیِ چیزی که می‌سنجد
آزموده شده و قرمز شده. یک سنجه که با برداشتنِ موضوعِ سنجش هم سبز بماند، گیت نیست.

## ★ فهرستِ تله‌های کشف‌شده

شرحِ کاملِ هرکدام در [`CLAUDE.md`](CLAUDE.md).

| تله | نشانه |
|---|---|
| **تخصیصِ `seq` باید سریالی باشد** | زیرِ `READ COMMITTED` دو نوشتنِ همزمان یک `seq` می‌گیرند و یکی می‌میرد — **۴۳ از ۵۰۰** append گم شد (ADR-037) |
| **سرور هیچ opی در سند نمی‌نویسد** | مهرِ `meta.schemaVersion`ِ سرور با نوشتنِ کلاینت تعارض می‌کرد و **نسخه‌ی schemaِ بورد بی‌صدا گم می‌شد** (F-1) |
| **updateِ تهی «نوشتن» نیست** | step2ِ یک تماشاگرِ تازه صفر op دارد؛ ردش یعنی `FORBIDDEN`ِ کاذب روی **هر** اتصالِ سالمِ `viewer` |
| **`markAlive` باید در `handleUpgrade` باشد** | با `noServer: true` رویدادِ `connection` **اصلاً emit نمی‌شود** → اولین تیکِ heartbeat **همه‌ی کلاینت‌ها را می‌کشت** |
| **«مودبانه» یعنی صبر تا رسیدنِ خداحافظی** | `close()` فقط دست‌دادن را شروع می‌کند؛ بازگشتِ فوری یعنی کلاینت **۱۰۰۶** می‌بیند نه ۱۰۰۱ |
| **اشتراکِ گذرگاه قبل از خواندن از دیتابیس، با بافر** | Redis pub/sub تحویل را تضمین نمی‌کند؛ پیامِ بینِ `load` و `subscribe` **هرگز** برنمی‌گردد |
| **قفل باید با Lua تمدید/رها شود** | «اگر مالِ من است» با دو دستور پنجره دارد → **دو صاحبِ همزمان** |
| **بینِ مرگِ صاحب و انقضای اجاره هیچ‌کس صاحب نیست** | updateِ کلاینت هیچ‌جا پایدار نمی‌شد و **بی‌صدا** گم می‌شد (F-2 → [ADR-041](../../ARCHITECTURE_DECISIONS.md#adr-041)) |
| **`SIGTERM` روی ویندوز handler اجرا نمی‌کند** | `exit code=1, signal=null`؛ پس `rt:shutdown` سرور را در همان فرایند بالا می‌آورد |
| **داکرِ خاموش شبیهِ رگرسیون است** | لاگِ سرور «اتصال پذیرفته شد» دارد ولی **«اتاق بارگذاری شد» ندارد**، و کلاینت `connected` نشان می‌دهد چون سوکت باز است |
