# هم‌بوم (Hamboom) — سند معماری و پرامپت ساخت (برای Opus 4.8 / Claude Code)

**نسخه ایرانی Miro | دامنه: hamboom.ir (خریداری‌شده)**

**تصمیمات پایه (طبق انتخاب‌های تو):**
- نام پروژه: **هم‌بوم (Hamboom)** — دامنه خریداری شده
- دامنه فاز اول: **گسترده** — پوشش وسیع فیچرهای میرو از همون ابتدا
- زیرساخت: **۱۰۰٪ داخل ایران** (آروان‌کلاود یا مشابه)
- روش ساخت: **تنها، با Claude Code / Opus 4.8 و ایجنت‌ها**

## ۱. یک نکته صادقانه قبل از شروع

"گسترده از همون ابتدا" با "تنها با AI agent" با هم جمع می‌شن، ولی به این معنا نیست که یک پرامپت کل اپ رو یک‌شبه می‌سازه. حتی خود میرو با صدها مهندس چند سال طول کشیده. راه‌حل عملی این نیست که دامنه رو کوچیک کنیم، بلکه اینه که:

1. یک **معماری واحد** طراحی کنیم که از روز اول همه ماژول‌های اصلی (بوم، همکاری زنده، تیم/ورک‌اسپیس، قالب‌ها، export، پرداخت) رو در نظر بگیره — نه اینکه بعداً وصله‌پینه بشه.
2. ساخت رو به **ماژول‌های مستقل** بشکنیم که هر کدوم می‌تونه یک "loop" یا فن‌اوت ساب‌ایجنت جدا باشه در Claude Code (دقیقاً همون الگویی که قبلاً روی کربنت پیاده کردی).
3. از **بلوک‌های متن‌باز آماده** برای سخت‌ترین بخش (موتور بوم + sync بلادرنگ) استفاده کنیم تا زمان توسعه به‌جای دوباره‌اختراع‌کردن چرخ، صرف بومی‌سازی و لایه بیزینسی بشه.

با این رویکرد، "گسترده" واقعاً ممکنه — فقط باید بدونی که پیاده‌سازی کامل، چند هفته تا چند ماه کار مداوم با ایجنت‌هاست، نه یک پرامپت.

## ۲. تصمیم معماری کلیدی: موتور بوم (Canvas Engine)

سه گزینه بررسی شد:

| گزینه | جمع‌بندی |
|---|---|
| **tldraw SDK** | فنی‌ترین/کامل‌ترین گزینه، ولی از نسخه ۲ به بعد **لایسنس تجاریه** (نه MIT) — برای production نیاز به خرید لایسنس از یک شرکت آمریکایی داری. با توجه به محدودیت‌های پرداخت ارزی و تحریم، این یک وابستگی خطرناک برای پروژه‌ایه که قراره کاملاً ایرانی باشه. **رد شد.** |
| **ساخت کاملاً سفارشی** (Konva.js + Yjs از صفر) | کنترل کامل، ولی برای یک نفر (even با AI agent) بازسازی موتور رندر + تعامل + selection + snapping از صفر، ماه‌ها زمان می‌بره. |
| **فورک/embed روی Excalidraw** ✅ پیشنهاد | Excalidraw کاملاً **MIT-licensed**، شامل بوم بی‌نهایت، شکل‌ها، فریم، متن، پیکان/کانکتور، embed تصویر، و یک سرور همکاری زنده متن‌باز (excalidraw-room) هست. می‌تونیم موتور رندرش رو به عنوان هسته بگیریم و لایه‌های میرویی (استیکی‌نوت رنگی، قالب‌ها، ورک‌اسپیس/تیم، پرمیشن، پرداخت، RTL کامل فارسی) رو دورش بسازیم. |

**تصمیم:** پایه روی Excalidraw (یا معماری مشابه با Konva.js برای بخش‌هایی که به سفارشی‌سازی عمیق نیاز داره) + **Yjs** برای لایه sync (CRDT واقعی، بهتر از broadcast ساده‌ی excalidraw-room برای مقیاس بزرگ‌تر). این ترکیب کاملاً متن‌باز و بدون وابستگی به لایسنس خارجی‌ه.

## ۳. معماری فنی کلی

```
┌─────────────────────────────────────────────┐
│  Frontend: React + TypeScript + Vite         │
│  - Canvas Engine: Excalidraw core (fork شده) │
│  - State: Zustand/Jotai + Yjs doc per board   │
│  - RTL کامل فارسی + i18n (fa اول، en بعداً)   │
├─────────────────────────────────────────────┤
│  Realtime Layer                              │
│  - Yjs CRDT + y-websocket (سرور خودمون)      │
│  - Redis Pub/Sub برای scale افقی چند instance│
│  - Presence: cursor، آواتار، حضور زنده        │
├─────────────────────────────────────────────┤
│  Backend API: Node.js (Fastify یا NestJS)     │
│  - Auth (JWT + refresh + OTP پیامکی)          │
│  - Board/Workspace/Team/Permission CRUD       │
│  - Template library                           │
│  - Billing webhook (زرین‌پال)                 │
├─────────────────────────────────────────────┤
│  Data                                         │
│  - PostgreSQL: کاربران، تیم، بورد متادیتا،     │
│    اشتراک/پرداخت                              │
│  - Redis: presence، session، cache، rate-limit│
│  - Object Storage (آروان، S3-compatible —     │
│    همون bucket-pattern که در my-service داری) │
│    برای export فایل، تصویر، اسکرین‌شات بورد   │
├─────────────────────────────────────────────┤
│  زیرساخت: ۱۰۰٪ آروان‌کلاود                    │
│  - Cloud Server / Cloud Container (K8s) برای  │
│    API و WebSocket server                     │
│  - Managed PostgreSQL + Redis (DBaaS آروان)   │
│  - Object Storage برای فایل‌ها                │
│  - Load Balancer + CDN + Anti-DDoS/WAF        │
│  - دامنه .ir برای کاهش ریسک فیلترینگ          │
└─────────────────────────────────────────────┘
```

**پرداخت:** زرین‌پال به عنوان درگاه اصلی (مستندات API و sandbox داره)، آیدی‌پی به‌عنوان بک‌آپ. قیمت‌گذاری ریالی و پلن‌های ماهانه/سالانه.

**احراز هویت:** با توجه به الگوی رایج کاربر ایرانی، شماره موبایل + OTP پیامکی (از طریق کاوه‌نگار یا ملی‌پیامک) به‌جای ایمیل به‌عنوان روش اصلی، با ایمیل به‌عنوان گزینه دوم.

### محیط توسعه لوکال (قبل از خرید هر سرویس ابری)

هیچ‌کدوم از حساب‌های آروان‌کلاود/زرین‌پال لازم نیست از روز اول آماده باشن. توسعه از همون ابتدا روی یک استک لوکال با Docker Compose انجام می‌شه:

- **PostgreSQL** و **Redis** به‌صورت کانتینر لوکال
- **MinIO** به‌جای Object Storage — چون MinIO دقیقاً همون S3 API استاندارد رو پیاده می‌کنه و ArvanCloud Object Storage هم S3-compatible‌ه، سوییچ بین این دو فقط با تغییر `endpoint`/`credentials` در env variable انجام می‌شه، بدون تغییر خط کدی از application logic.
- **زرین‌پال** یک محیط sandbox/تست عمومی داره که بدون تاییدیه‌ی کسب‌وکار قابل استفاده‌ست — یعنی می‌شه کل جریان پرداخت (checkout, callback, verify) رو کامل ساخت و تست کرد، و فقط در آخرین قدم، merchant ID واقعی (بعد از گرفتن تاییدیه) جایگزین sandbox بشه.
- **DNS دامنه** هم چون هنوز سروری وجود نداره، معنایی نداره الان تنظیم بشه — کاملاً می‌مونه برای زمان دیپلوی.

نتیجه: تنها جایی که ممکنه در انتهای کار یک وقفه‌ی چندروزه بسازه، **فرآیند تاییدیه‌ی زرین‌پال**‌ه (چون به احراز هویت کسب‌وکار وابسته‌ست، نه کدنویسی). بقیه موارد (آروان، DNS) در عرض چند ساعت قابل راه‌اندازی‌ان و می‌تونن دقیقاً همون روزی انجام بشن که کد آماده‌ی دیپلویه.

## ۴. مدل داده اصلی

- **User**: id، شماره‌موبایل/ایمیل، نام، آواتار، پلن فعلی
- **Team/Workspace**: id، نام، مالک، اعضا (نقش: Admin/Editor/Viewer)
- **Board**: id، workspace_id، عنوان، thumbnail، تاریخ آخرین ویرایش، وضعیت (private/shared-link/public)
- **BoardDoc**: نمایش Yjs doc (باینری snapshot در دیتابیس + real-time در حافظه)
- **Element**: نوع چندریختی (sticky, shape, text, connector, frame, image, embed) — این‌ها داخل Yjs doc زندگی می‌کنن نه لزوماً به‌عنوان ردیف جدا در Postgres
- **Template**: id، دسته‌بندی (بیزینس مدل کانواس، رتروسپکتیو، فلوچارت، نقشه ذهنی، Sprint Planning...)، محتوای اولیه بورد
- **Comment**: element_id، board_id، author، متن، mention
- **Subscription**: user/team_id، پلن، وضعیت پرداخت، تاریخ تمدید
- **AuditLog / VersionSnapshot**: برای تاریخچه نسخه و بازگشت به عقب

## ۷. نقشه‌راه اجرا با Claude Code (تنها + ایجنت) — دقیق

### مرحله صفر: اسکلت مشترک (یک‌بار، قبل از هر loop)
قبل از شروع لوپ‌ها، این‌ها رو در یک session معمولی (نه loop) بساز:
- ساختار مونوریپو: `apps/web`، `apps/api`، `apps/sync-server`، `packages/shared-types`، `infra/`
- `packages/shared-types`: تعریف اولیه‌ی (حتی خام) Element ها (sticky, shape, connector, frame, ...)، User، Team، Board، و API contract پایه. این پکیج **قرارداد مشترک** بین همه‌ی loop هاست.
- یک `CLAUDE.md` در ریشه ریپو: خلاصه محصول، محدودیت‌های سخت (بدون tldraw، فقط MIT، زیرساخت آروان، پرداخت زرین‌پال)، ساختار پوشه‌ها، لینک به همین سند.
- هر ماژول هم یک `CLAUDE.md` مخصوص خودش داخل پوشه‌اش می‌گیره (مثلاً `apps/web/CLAUDE.md`) که فقط جزئیات همون ماژول رو داره — این‌طوری وقتی یک session روی اون پوشه کار می‌کنه، فقط context مرتبط رو می‌بینه.

### گراف وابستگی ماژول‌ها (این ترتیب اجرا رو تعیین می‌کنه)
```
Phase A (کاملاً مستقل از هم — می‌تونن هم‌زمان اجرا بشن):
  canvas-core   ─┐
  backend-api   ─┼─► نقطه‌ادغام ۱
  infra         ─┘

Phase B (به خروجی Phase A وابسته‌ان):
  realtime-sync  ← به element schema از canvas-core نیاز داره
  billing        ← به user/team model از backend-api نیاز داره
        │
        ▼
   نقطه‌ادغام ۲

Phase C:
  admin-dashboard ← به همه API های Phase A/B نیاز داره
```

### چطور واقعاً موازی اجراشون کنیم: git worktree
به‌جای این‌که سه session رو پشت‌سرهم توی یک پوشه اجرا کنی (که باعث تداخل فایل می‌شه)، از `git worktree` استفاده کن — هر ماژول یک working directory جدا از همون ریپو می‌گیره:

```bash
git worktree add ../hamboom-canvas-core feature/canvas-core
git worktree add ../hamboom-backend-api feature/backend-api
git worktree add ../hamboom-infra feature/infra
```

حالا سه ترمینال جدا باز کن، توی هرکدوم Claude Code با Opus 4.8 اجرا کن، و واقعاً هم‌زمان پیش ببر — بدون این‌که یکی فایل‌های دیگری رو دست بزنه.

### اجرای هر loop (داخل هر worktree)
1. `/goal` رو با هدف دقیق همون ماژول تنظیم کن (مثلاً canvas-core: «فورک Excalidraw، حذف بخش‌های غیرضروری، RTL کامل، پالت استیکی‌نوت میرو-استایل، expose کردن event ها طبق interface تعریف‌شده در packages/shared-types»).
2. اول ازش بخواه فقط `TODO.md` مخصوص همون ماژول رو بسازه (مرحله‌ی برنامه‌ریزی، نه کد) و تاییدش کن.
3. بعد `/loop` رو روش اجرا کن تا آیتم‌های TODO یکی‌یکی تیک بخورن.
4. آخر هر session (قبل از پر شدن context)، ازش بخواه یک `PROGRESS.md` بنویسه: چی انجام شد، چه تصمیمی گرفته شد، قدم بعدی چیه — این‌طوری session بعدی (همون روز یا فردا) بدون از دست‌دادن context ادامه می‌ده.

### نقطه‌ادغام (Integration Checkpoint)
بعد از تمام‌شدن Phase A:
1. سه برنچ رو merge کن به `main`.
2. یک session تازه (بررسی معمولی، نه loop) باز کن و بخواه canvas-core و backend-api رو به هم وصل کنه و یک smoke test بزنه (باز کردن بورد، ذخیره یک عنصر، لود مجدد).
3. اگه `packages/shared-types` نیاز به تغییر داشت، این تغییر رو **خودت دستی تایید کن** قبل از ادامه — چون این فایل قرارداد مشترک بین ماژول‌هاست و تغییر ناهماهنگ روی این فایل باعث شکستن ماژول‌های دیگه می‌شه.

همین الگو رو برای Phase B (realtime-sync + billing) و Phase C (admin-dashboard) تکرار کن.

### نکته درباره‌ی مصرف token/هزینه
اجرای واقعاً هم‌زمان چند session یعنی مصرف بیشتر توکن/زمان هم‌زمان. اگه محدودیت داری، همون گراف وابستگی رو رعایت کن ولی loop ها رو پشت‌سرهم (نه هم‌زمان) اجرا کن — فقط سرعت کار عوض می‌شه، نه ترتیب منطقی.

## ۸. پرامپت نهایی — آماده برای Opus 4.8 / Claude Code

این پرامپت رو به عنوان kickoff prompt در Claude Code (با مدل Opus 4.8) اجرا کن. طراحی شده که اول یک plan دقیق تولید کنه، نه اینکه مستقیم کد بزنه:

```
نقش تو: معمار ارشد + مهندس ارشد فول‌استک برای ساخت «هم‌بوم» (Hamboom) —
یک پلتفرم وایت‌بورد آنلاین مشابه Miro، مخصوص بازار ایران، به‌صورت کامل
داخلی و ریالی. دامنه پروژه hamboom.ir قبلاً خریداری شده.

بستر: من به‌تنهایی و با کمک تو (از طریق Claude Code CLI) این پروژه رو
می‌سازم. قراره کار به چند ماژول مستقل (loop) تقسیم بشه.

محدودیت‌های سخت:
- هیچ کتابخانه یا سرویس تجاری خارجی که نیاز به لایسنس/پرداخت ارزی داشته
  باشه استفاده نشه (مثلاً tldraw SDK ممنوعه چون از نسخه ۲ لایسنس تجاریه).
  فقط پکیج‌های MIT/Apache-2.0/BSD.
- زیرساخت هدف نهایی: ۱۰۰٪ قابل هاست روی آروان‌کلاود (Cloud
  Server/Container/K8s، Managed PostgreSQL، Managed Redis، Object
  Storage سازگار با S3). **ولی هنوز هیچ حساب آروان یا زرین‌پال واقعی
  خریداری نشده** — پس کل توسعه باید از روز اول با یک استک لوکال
  Docker Compose قابل اجرا باشه:
  - PostgreSQL و Redis به‌صورت کانتینر لوکال
  - MinIO به‌جای Object Storage (S3 API استاندارد، دقیقاً همون
    interface که ArvanCloud Object Storage هم پیاده می‌کنه — سوییچ
    بین این دو باید فقط با تغییر env variable (`endpoint`,
    `access_key`, `secret_key`) ممکن باشه، بدون تغییر کد اپلیکیشن)
  - برای پرداخت، از sandbox عمومی زرین‌پال استفاده کن (merchant ID
    تستی که بدون تاییدیه‌ی کسب‌وکار در دسترسه) — کل جریان
    checkout/callback/verify باید کامل ساخته و تست بشه، طوری که در
    آخرین مرحله فقط merchant ID واقعی جایگزین بشه.
- پرداخت نهایی: زرین‌پال (اصلی) + آیدی‌پی (پشتیبان، در فاز بعد).
  بدون Stripe/PayPal.
- احراز هویت اصلی: شماره موبایل + OTP پیامکی (کاوه‌نگار یا مشابه)،
  ایمیل به‌عنوان گزینه دوم.
- تمام UI باید RTL کامل و فارسی native باشه (نه ترجمه‌ی سرهم).
```

## ۹. چک‌لیست همین الان (نسخه واقع‌بینانه — همه‌چیز جز کدنویسی، به تعویق افتاده)

طبق تصمیم تو، همه‌ی خریدها/ثبت‌نام‌ها (آروان، زرین‌پال، ثبت برند) می‌رن برای انتهای کار. یعنی همین امروز فقط این‌ها لازمه:

1. **مخزن گیت** — یک ریپو خصوصی برای مونوریپو بساز (`hamboom`) و همین سند رو به‌عنوان اولین commit (`docs/PROJECT_SPEC.md`) داخلش بذار.
2. **اجرای پرامپت kickoff** (بخش ۸) — در یک session تازه‌ی Claude Code با Opus 4.8، طوری که خروجی‌اش شامل تنظیم `docker-compose.yml` لوکال (Postgres + Redis + MinIO) هم باشه.
3. شروع کدنویسی ماژول **canvas-core**، بدون نیاز به هیچ حساب ابری.

**لیست کارهایی که برای «انتهای کار» (زمان دیپلوی) گذاشته شدن — فقط برای یادآوری، الان کاری لازم نیست:**
- ثبت‌نام و تاییدیه‌ی زرین‌پال (⚠️ چون تاییدیه‌اش چندروزه، وقتی حس کردی چند هفته به پایان کار مونده، همون موقع شروعش کن، نه دقیقاً روز آخر)
- ساخت حساب آروان‌کلاود و پروویژن Cloud Server/Container، Object Storage، Managed DB
- تنظیم DNS دامنه `hamboom.ir` روی آروان
- ثبت برند «هم‌بوم» در اداره مالکیت معنوی

بعد از این، اولین چیزی که واقعاً باید کدنویسی بشه ماژول **canvas-core** هست (فورک Excalidraw) — چون بقیه ماژول‌ها (sync، backend، billing) بهش وابسته‌ان.
